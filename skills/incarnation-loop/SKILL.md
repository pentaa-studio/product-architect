# Incarnation Loop

Chapter 10. Operational map of how sense becomes form and function.

## Visual reference

Diagram: `docs/methodology/butterfly-process/diagrams/ch10-incarnation-loop.png`

Source: [FigJam — Pentaa App Builders](https://www.figma.com/board/7YQbMLEPV43LCcFzGeBoQP/Pentaa---App-Builders?node-id=2-885)

## Hub — IMAGINE

Central conversion point. Artefacts:

- **In**: Personas, User Journey, User Stories, KPI
- **Out**: Backlog, Specs, Prototype
- **Stakeholders**: Product team, Board/CEO

### Flows from IMAGINE

| Target | Label |
|--------|-------|
| IDENTIFY | Explore human context |
| SALE | Explore Opportunities |
| DESIGN | Generate Creative Shapes |
| ← DEVELOP | Functional Testing |

## Left wing — INPUT (Data Sourcing)

| Node | Team | Artefacts |
|------|------|-----------|
| IDENTIFY | Support | Support Feedbacks |
| SALE | Marketing | Analytics/BI, Ads/Partnerships, Business Model |

**Core**: Context, Priority, Customers

**Vertical link**: IDENTIFY ↔ SALE — *Understand Customers*

## Right wing — OUTPUT (Data Driven)

| Node | Team | Artefacts |
|------|------|-----------|
| DESIGN | Design | UI, UX, Prototype |
| DEVELOP | Tech | Technical Requirements, Front/Back Dev |

**Coordination core**: Shapes, Timing, Users → feeds Backlog, Specs, Prototype

**Vertical link**: DESIGN ↔ DEVELOP — *Make Design Functional*

## Workflow for agents

1. Place current work on the map (which node?)
2. Verify IMAGINE artefacts exist before DESIGN/DEVELOP
3. Ensure Functional Testing feeds back to IMAGINE
4. Keep INPUT wing active during OUTPUT work (not sequential handoff)

## Output

- Team placement table for current initiative
- Missing artefact gaps (e.g. shipping DEVELOP without Specs)
- Loop health check: is Functional Testing closing back to IMAGINE?
